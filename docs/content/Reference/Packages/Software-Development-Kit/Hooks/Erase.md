## Tokens
When the event is emitted, all the identifiers passed by the user (to the [*Erase* sub-command][erase-subcommand]{data-preview} of `awabbre`) are passed as is to the hook function.

[erase-subcommand]: ../../../Awabbre-Manager/Arguments/Sub-Commands/Erase.md

## Example uses
Validating requests
:   The user might erase an awabbre that another awabbre depends on.  
    In this case, the package should warn the user about the potential consequences of erasing the awabbre, and ask if the user wants to re-add it, or also remove the dependent awabbre. The user should be able to bypass this prompt.  
    Such a warning shouldn't be brought up in non-interactive mode.

Suggesting a fixed version
:   When the user erases an awabbre, the hook can scan for a known typical error, search for similar awabbre in repositories, and also suggest a fixed version of the awabbre to the user.  

:   The hook should display a message to the user with the possible mistake, prompt the user to add a similar awabbre from the repositories, or to add an automatically fixed version.

Logging the event for other uses
:   The event can be logged for various purposes—like debugging, statistics, and reporting

Garbage collection
:   There could be leftover data (runtime or static) related to the erased awabbre that might be generated by another wrapper, hook, or expander. The hook can be used to clean up such data.
